## Specific contribution hypothesis

A creator can demonstrate one supported physical joint, confirm its type and observed travel, and obtain a reusable normalized control independent of a particular character. The product makes ambiguity, common prop movement, manual corrections, tracking loss and backend placement visible. A deliberately bounded planar controller could make authoring faster and more understandable than manual configuration while preserving low latency.

That is a **hypothesis for evaluation**, not a proven research novelty or claim to have invented physical puppetry, object tracking, joint fitting, or motion retargeting. The held-out study is still outstanding. Learned features do not yet establish an overall usability or robustness advantage over the classical baseline.

## Deployment references

- [Official ONNX Runtime QNN EP](https://onnxruntime.ai/docs/execution-providers/QNN-ExecutionProvider.html): static supported graphs, quantization, HTP configuration, profiling and disabling CPU fallback.
- [Official Qualcomm AI Hub Workbench compilation](https://workbench.aihub.qualcomm.com/docs/hub/compile_examples.html): ONNX/QAIRT targets and device-specific context binaries. Exporting ONNX alone is insufficient.
- [Official QNN Python package](https://pypi.org/project/onnxruntime-qnn/): current package history was checked separately from the older deployment pin. The included worker pins 1.22.2, whose Windows ARM64 wheels were verified in PyPI metadata; local target execution remains unverified.
- [Challenge reference](https://unstop.com/competitions/crp-snapdragon-ai-lab-build-present-challenge-qualcomm-1748893/amp): application is intended for Snapdragon-powered HP PCs. No entry was submitted and no one was contacted.
